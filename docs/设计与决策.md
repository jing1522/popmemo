# PopMemo · 设计与决策存档

> 只给自己用的安卓小 App。这份文件记录「为什么这么做」，代码只记录「怎么做的」。

## 一、它是什么

**解锁手机 → 弹出一张小卡片，显示还没办完的事 → 左右一划就处理掉。**

三个不可妥协的点：

1. **挡在你面前** —— 不是通知，是盖在屏幕上的卡片，不看不行
2. **少而准** —— 一次最多 3 条，多了等于没弹
3. **一划就处理** —— 不用找按钮，不用进 App

## 二、为什么做（痛点排序）

| 痛点 | 严重程度 | 对应解法 |
|---|---|---|
| 写了备忘录还是会忘 | 最高 | 每次解锁都出现，直到办完 |
| 写起来难受 | 高 | 一行输入 + 语音，回车即存 |
| 关闭要简单 | 中 | 左右滑 |

关键判断：**核心不是「记得方便」，是「必须看见」**。所以任何减少曝光的设计，都在削弱产品本身。

## 三、定下来的规则（结论，不是提议）

1. **只有「办完」才降低曝光。** 没办完的事，每次解锁都该出现。
2. **不做频率节流。** 删掉「30 分钟一次」和「一天最多 3 次」——它们假设「烦」比「忘」严重，方向是反的。
3. **限的是条数，不是次数。** 每次最多 3 条，按「最久没被确认」排序轮转，每条都会周期性转到眼前。
4. **左右滑有语义：**
   - 右滑 = 办完了 → 真正消失
   - 左滑 = 还没弄 → 不消失，下次排更靠前
   - 点空白 = 只是看一眼，状态不变
5. **弹窗上要有「+」。** 解锁那一秒最容易想起事情，这一刻就能记。
6. **没有开关。** 装完就永远开着，开机自启。少一个状态就少一个能忘的地方。
7. **星标反转。** 新写的默认就要弹；只有顺手记的琐事才需要取消。
8. **深色卡片。** 半夜解锁不刺眼，这是真实需求不是审美。
9. **常驻通知当第二条命。** 显示「还有 N 件事」，弹窗被划掉后它还在。
10. **只针对自己的机型写。** 不做向下兼容，`minSdk` 直接顶到自己的系统版本。
11. **截止日，不是提醒时间。** 人不想为每条事去设提醒；只需要说「哪天之前要交」，露面强度由它自己算：
    - 已过期 / 今天 → 最高优先，每次解锁必占一个卡位
    - 1–3 天 → 次高，优先于没日期的
    - 4–7 天 → 再次
    - >7 天 / 没设 → 纯轮转（最久没露面的先出）；同档内有日期的仍优先于没日期的
    - 设日期只给五个快捷档（今天／明天／三天后／一周后／选日期），不用打字

## 五、还没解决的风险（按致命程度）

1. **厂商杀后台。** 小米/华为/OPPO/vivo 会清掉服务。被杀了不会报警，你只会觉得「怎么最近不弹了」——这是最致命的，因为它悄无声息。
2. **重启后自启。** Android 15 起，开机拉起这类前台服务可能被系统拒绝，目前用 try/catch 兜着，兜不住就要用户手动开一次 App。
3. **悬浮窗权限。** 没给权限时，弹窗静默失效，用户不会知道。
4. **全部只验证了「能编译」。** 真机行为一次都没跑过。
